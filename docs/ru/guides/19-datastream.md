# 19. DataStream

DataStream — способ, которым части игры общаются, ничего не зная друг о друге: кто угодно **публикует** сообщение с
**тегом**, кто угодно **подписывается** на тег. Монетка не ищет правила игры, HUD не держит игрока: у них общее только
имя тега и форма данных. Тот же поток связывает компоненты на TypeScript и C# (руководство 18) и может связывать потоки
выполнения.

## Публикация и подписка

```ts
// компонент на TypeScript
const subscription = this.Engine.Stream.Subscribe<{ Coin: string; }>( "Coin.Collected", ( coin ) => {
	this.Engine.Ui.Toast( `${ coin.Coin } picked up` );
} );
// ...где-то ещё, ничего не зная о подписчике
this.Engine.Stream.Publish( "Coin.Collected", { Coin: this.Entity.Name } );
// когда больше не нужно (OnDestroy)
subscription.Dispose();
```

```csharp
// компонент на C#: тот же тег, свой тип
public sealed record CoinCollected( string Coin );

public override void Start() => Engine.Stream.Subscribe<CoinCollected>( "Coin.Collected", coin => Engine.Log.Info( coin.Coin ) );
```

- `Publish` доставляет **синхронно** подписчикам тега в порядке подписки. Подписчик, бросивший исключение, попадает в
  журнал, остальные всё равно получают сообщение.
- `Post` вместо этого ставит сообщение в очередь (кольцевой буфер), а `Flush` доставляет очередь по порядку; движок
  вызывает его раз за кадр.
- Тег — строка или `DataTag.For<T>( "Имя" )`: теги интернируются, поэтому доставка — это поиск в массиве, а не хеш
  строки, а параметр типа держит публикующих и подписчиков тега на одном типе.
- Отписаться посреди доставки можно; подписчик, добавленный во время доставки, получит следующее сообщение.

## Операторы (как в R3)

`Observe( tag )` даёт сообщения тега как `Observable` с самыми ходовыми в играх операторами R3 от Cysharp:

```ts
this.Engine.Stream.Observe<Damage>( "Damage" )
	.Where( ( d ) => d.Amount > 0 )
	.Select( ( d ) => d.Source )
	.DistinctUntilChanged()
	.Take( 3 )
	.Subscribe( ( source ) => this.Engine.Ui.Toast( `hit by ${ source }` ) );
```

`Where`, `Select`, `Skip`, `Take` (отпускает тег после последнего значения), `DistinctUntilChanged`, `Observable.Merge`.
Значения приходят синхронно, на каждое значение ничего не выделяется. В C# те же операторы у `Engine.Stream.Observe<T>`.

`ReactiveProperty<T>` — значение, которое сообщает о своих изменениях: подписчик сразу получает текущее значение, затем
каждое изменение; `PublishTo( stream, "Score" )` дополнительно публикует изменения в тег, так что HUD, система
сохранений или компонент на C# могут следить за ним, не имея ссылки на владельца.

## Между TypeScript и C#, между потоками

`Connect( link )` соединяет поток с другим: с потоком компонентов C# (это делает движок), с потоком другого воркера
(`WorkerLink( port )`) или два потока одного потока выполнения (`LinkStreams( a, b )`). Через связь:

- сообщение уходит только в те теги, на которые подписана другая сторона (подписки объявляются и снимаются, когда уходит
  последний подписчик): тег, который там никто не слушает, ничего не стоит;
- сообщения идут одной пачкой MessagePack за каждый `Flush`, на другой стороне доставляются, но обратно не отправляются;
- значения — простые данные: числа, строки, булевы, массивы, объекты, массивы байтов. В C# `MessageMapper` превращает
  их в класс, структуру или record подписчика (члены сопоставляются по имени: сначала точно, потом без учёта регистра;
  позиционные records — через конструктор; перечисления — числами) и записывает значения C# обратно простыми данными.

## MessagePack

Двоичный формат пачек (и вообще двоичный формат движка) — MessagePack, с кодеком для каждого языка: `@cse/datastream`
(`Encode`, `Decode`, `MessagePackWriter`, `MessagePackReader`) и `CSEngine.Messaging` (`MessagePack`, `MessagePackWriter`,
`MessagePackReader`). Для одного и того же значения оба пишут одинаковые байты: их проверяют по одному файлу векторов,
`Modules/Common/DataStream/Tests/Vectors.json`.

Исходники: `Modules/Common/DataStream` (TypeScript: `Source/`, C#: `DotNet/`).
