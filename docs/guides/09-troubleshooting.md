# 09. Если что-то не работает

Идём от симптома к причине. Сначала всегда открой **консоль браузера** (F12): ошибки воркеров и скриптов пишутся туда,
причём скриптовые — строкой вида `[Script] ИмяКласса.Хук threw on entity "…" (#id)`.

## Запуск и сборка

| Симптом | Причина → что делать |
|---|---|
| При старте тост *«Physics failed to load…»*, предметы висят | wasm физики не собран или не найден. Собери (`Physics/Bridge/BUILD.md`), проверь, что есть `Binaries/Physics/Release/net10.0/browser-wasm/AppBundle/_framework/dotnet.js` |
| Экран загрузки висит дольше ~30 с | Физика не подала сигнал ни «готова», ни «ошибка»: смотри консоль на 404/ошибки `dotnet.js`. Через 30 с движок продолжит без физики |
| `pnpm typecheck` ругается на `.vue` | Нужен `vue-tsc` (он в скриптах); обычный `tsc` не понимает `.vue` |
| `pnpm dev`: «Port 5173 is already in use» | Dev-сервер уже запущен (возможно, в другом терминале или задачей VS Code). Порт закреплён (`strictPort`), чтобы задачи и отладка VS Code всегда знали адрес |
| `pnpm test` падает с «Coverage … does not meet global threshold (100%)» | Тесты прошли, но новый код покрыт не полностью. Файл и метрика указаны в сообщении; подробный отчёт — `coverage/index.html` |
| `pnpm test:e2e`: «Executable doesn't exist» | Не установлен браузер для Playwright: `pnpm exec playwright install chromium` (один раз) |
| E2E упал | Причина печатается в терминале; для упавшего теста сохраняется трейс: `pnpm exec playwright show-trace test-results/<тест>/trace.zip` (в CI — ещё HTML-отчёт в артефактах). Тесты падают и на любой ошибке или предупреждении в консоли браузера, и на Warning/Error в логе игры — сообщение теста говорит, что именно было |
| В консоли жалобы про `Tools/LogServer.mjs` | В присланном мне архиве этого файла не было; если его нет и у тебя — sidecar-логгер не стартует, игре это не должно мешать (логи идут в консоль) |
| Изменения скрипта не видны | Воркеры подхватывают изменения полной перезагрузкой страницы; Vue-компоненты — «на лету» |

## Мышь и меню

| Симптом | Причина → что делать |
|---|---|
| Нажимаю Play — ничего, мышь не захватилась | Браузеру нужен жест пользователя, и после Esc есть короткая пауза: подожди секунду и кликни ещё раз. Меню останется на экране |
| Esc не возвращает в игру | Пока мышь захвачена, Esc уходит браузеру и открывает меню; вернуться — клик по **Resume** |
| Клавиши «залипают» после Esc/Alt-Tab | Не должны: при потере фокуса и захвата движок сбрасывает ввод. Если залипает — это баг, пришли шаги |
| Пробел прокручивает страницу | Не должен, пока мышь захвачена. Вне захвата — это обычное поведение браузера |

## Сцены и сущности

| Симптом | Причина → что делать |
|---|---|
| Сцены нет в меню | Не зарегистрирована в `Game/GameScenes.ts` |
| «Scene … is already registered» | Повторяющийся `id` |
| Объект не виден | Нет `MeshRenderer`/не задан `Mesh`; или он за камерой; или камеры нет в сцене |
| Объект виден, но проваливается или висит | Нет тела; или физика не собрана; или слой/маска не пересекаются с полом |
| `Comp(...)` — ошибка типа | Поле, которого нет у компонента, или неверный тип значения — так и задумано, исправь по подсказке компилятора |
| Компонент «не работает» | `Enabled = false`; сущность `Active = false`; не `override` (опечатка в хуке — компилятор подскажет); хук другого такта (кадр ≠ физика) |
| `RequireComponent` бросил ошибку | На сущности нет такого компонента (или он в другой сущности) — проверь манифест |
| Ссылка на сущность «умерла» после рестарта | Не храни сущности между сценами, находи заново в `Start` |

## Физика и персонаж

| Симптом | Причина → что делать |
|---|---|
| Игрок проваливается в пол при появлении | Стартовая позиция слишком низко. Центр капсулы должен быть ≥ ~1.0 м над полом |
| Игрок не может подняться на ступеньку | Автоступенек нет (гайд 05). Рампа ≤ 46° или блок, на который надо запрыгнуть |
| Игрок «скользит» по лифту | В манифесте `KinematicBody` стоит **до** скрипта движения (гайд 04) — поменяй порядок |
| Телепортировал игрока, он улетел | Используй `characterBody.Teleport(...)` (обнуляет скорость) |
| Скорость, выставленная из `Update`, «пропала» | Меняй `Velocity` персонажа из `OnPhysicsUpdate` или колбэков физики (гайд 05) |
| Пуля летит сквозь тонкую стену | Нужен компонент `Projectile` (а не `RigidBody`), либо `ContinuousDetection` и более толстая стена |
| Предметы не сталкиваются | Слои и маски: оба тела должны «видеть» друг друга (гайд 04) |
| `OnCollisionEnter` не вызывается для игрока и пола | Так и есть: события контактов идут, когда в паре есть динамическое тело или триггер. «Стою на земле» — `IsOnFloor` |
| Команда телу сразу после `Spawn` игнорируется | Отдай её из `Start` другого компонента (гайд 03) |
| Ящик на платформе соскальзывает | Платформа движется слишком рывками — двигай её из `OnPhysicsUpdate` (а не из `Update`) и скриптом **до** `KinematicBody` |

## Интерфейс

| Симптом | Причина → что делать |
|---|---|
| HUD пустой | Строки ставят в `OnUIUpdate`; HUD скрыт во время меню и загрузки |
| Нужна своя кнопка/шкала | Схема из пяти мест — гайд 06 |
| Меню выглядит иначе, чем хочется | Только `Source/Ui/**/*.vue` (обычный Quasar), логику в `UiController` не трогай |

## Как сузить проблему

1. **Тесты**: `pnpm test` гоняет весь рантайм без браузера. Если тест на твою сцену проходит, а в браузере не работает — проблема в физике (wasm), рендере или UI,
   а не в скриптах. Шаблон теста сцены — `Tests/GameLogicRuntime.test.ts` (поддельные порты в `Tests/Harness.ts`).
2. **Отключи лишнее**: убери компоненты из манифеста по одному, пока не найдёшь виновника.
3. **Смотри команды физике**: в тестах `harness.AllPhysicsCommands()` показывает, что именно скрипты отправили физическому воркеру, — это быстро отвечает на вопрос «я вообще это попросил?».
