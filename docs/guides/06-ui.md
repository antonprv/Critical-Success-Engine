# 06. Интерфейс

В браузере у воркеров нет DOM, а Vue и Quasar без DOM не живут. Поэтому интерфейс разделён так же, как звук:

```
GameLogic ──(сцены, прогресс загрузки, HUD, тосты)──▶ UiWorker ──(патчи состояния)──▶ главный поток: Vue/Quasar ──рисует
GameLogic ◀──(load-scene, set-capture)────────────── UiWorker ◀──(pointerlockchange, клики)── главный поток
```

- **UiWorker** (`Workers/Ui/UiController.ts`) хранит *состояние* и *логику*: что показывать (загрузка / меню / HUD) и когда
  игра получает мышь. Это чистый TypeScript без DOM — он тестируется (`Tests/UiController.test.ts`).
- **Главный поток** только *рисует* состояние (`Source/Ui/*.vue`) и пересылает DOM-события. В нём нет игровой логики.
- **Скрипты** игры вообще не знают ни о воркере UI, ни о Vue — они зовут `this.Engine.Ui`.

## Что умеет `this.Engine.Ui` из скрипта

```ts
ui.SetHud("score", `Score: ${n}`);                 // строка текста слева сверху; ключ → своя строка у каждого компонента
ui.SetHud("score", null);                          // убрать строку
ui.SetBar("hp", "HP 40/100", 0.4);                 // шкала (0..1) с подписью; SetBar("hp", "", null) — убрать
ui.Toast("Подобрал ключ");                         // всплывающее сообщение справа сверху
ui.ClearHud();                                     // стереть всё (делается само при смене сцены)
```

Обновление HUD обычно кладут в `OnUIUpdate(ui, dt)`. Изменения копятся и уходят пачкой не чаще 10 раз в секунду.

## Меню паузы, мышь и загрузка (как это работает)

1. При старте виден экран загрузки (Vue + `q-linear-progress`), прогресс присылает `SceneManager` по ходу загрузки сцены.
2. Загрузилась сцена → UI просит у браузера захват мыши (`requestPointerLock`).
3. Браузер разрешил → `playing`: меню скрыто, игре включается ввод. **Не разрешил** (нужен клик пользователя) → меню с кнопкой **Play**.
4. **Esc** — браузер сам отпускает мышь; UI это видит и открывает меню, а у игры отключает ввод.
5. Выбрал сцену → экран загрузки → снова захват мыши. Если браузер отказал (клик был давно) — меню с кнопкой **Resume**: один клик, и игра твоя.

Если игра сама перезагружает сцену (рестарт по `R`, как в Coin Hunt), а мышь при этом остаётся захваченной, UI сразу возвращается
в `playing` — меню не мелькает.

Хотелось бы «нажал Esc ещё раз, чтобы вернуться» — так не получится: пока мышь захвачена, браузер не отдаёт странице Esc. Поэтому возврат — кликом.

## Добавляем шкалу здоровья — полный путь

Это пример, **как расширять UI своим виджетом**. Шкала уже есть в движке (`SetBar`); вот как она была добавлена — по этой же схеме
добавляется любой другой виджет (счётчик патронов, прицел, карта…). Всего пять мест:

**1. Протокол** — `Workers/Protocol/UiProtocol.ts`: тип данных, место в состоянии и сообщение от GameLogic:

```ts
export interface UiBar { id: string; label: string; value: number; }
export interface UiHudState { visible: boolean; lines: string[]; bars: UiBar[]; }
// … в GameLogicToUiMessage:   | { type: "bars"; bars: UiBar[]; }
```

**2. Сервис для скриптов** — `Engine/Services/UiService.ts`: `SetBar(...)` кладёт данные в словарь, `Flush()` отправляет изменения сообщением `bars`.

**3. Логика UI** — `Workers/Ui/UiController.ts`: принимает сообщение и обновляет состояние (если виджет зависит от фазы — например, прятать на паузе — решает тут):

```ts
case "bars":
	this._state.hud = { ...this._state.hud, bars: message.bars };
	this.PushState({ hud: this._state.hud });
	break;
```

**4. Отрисовка** — `Ui/components/Hud.vue` получает `bars` и рисует `q-linear-progress`; `Ui/App.vue` передаёт их пропсом.

**5. Использование** в скрипте (рабочий код — `Game/GuideExamples/HealthBar.ts`):

```ts
import { Component } from "../../Engine/Core/Component";
import type { UiService } from "../../Engine/Services/UiService";

/** Hit points with a bar on the HUD. Anything that wants to hurt this entity calls `Damage`. */
export class Health extends Component {
	public Max = 100;
	public Current = 100;

	public Damage(amount: number): void {
		this.Current = Math.max(0, this.Current - amount);
	}

	public override OnUIUpdate(ui: UiService): void {
		ui.SetBar("hp", `HP ${this.Current}/${this.Max}`, this.Current / this.Max);
	}
}
```

```ts
Ent("Hero", [Comp(Health, { Max: 100, Current: 60 })]),
// где-то в ловушке:   hero.GetComponent(Health)?.Damage(10);
```

Принцип: **данные идут в одну сторону, события — в другую**. Скрипт ничего не знает про Vue; Vue ничего не знает про игру;
между ними только типизированные сообщения. Хорошо, когда виджет умещается в «данные → отрисовка». Если виджет *интерактивный*
(кнопка, меняющая игру), добавь ещё сообщение в обратную сторону (`UiToGameLogicMessage`) и обработай его в `GameLogicRuntime.OnUiMessage`.

## Меню: как добавить свою кнопку

Список сцен в меню берётся из `SceneRegistry` автоматически (поля `name` и `description` манифеста). Ещё одну кнопку (скажем, «Настройки»)
добавляют так же, как шкалу: поле в `UiMenuState` → отрисовка в `PauseMenu.vue` → сообщение вида `{ type: "open-settings" }`
в `UiProtocol` → обработчик. Файл `PauseMenu.vue` — обычный Quasar (`q-card`, `q-list`, `q-btn`), любая документация Quasar к нему применима.

## Тосты и Quasar

Тосты — `Notify` из Quasar (позиция/длительность заданы в `Ui/CreateUi.ts`). Тёмная тема включена там же. Quasar-компоненты подключаются автоматически
по использованию в шаблонах (`q-btn`, `q-card`…), вручную импортировать не нужно.

## Если не работает

| Симптом | Причина |
|---|---|
| HUD пустой | Строки ставятся только из `OnUIUpdate`/`Update`; проверь, что компонент включён; HUD скрыт, пока открыто меню или идёт загрузка |
| Тост не появляется | Они уходят через UiWorker; если воркер упал — смотри консоль |
| После загрузки сцены сразу меню «Resume» | Браузер не дал мышь без свежего клика — это норма, нужен один клик |
| Esc не возвращает в игру | См. выше — возврат кликом по **Play/Resume** |
| Нужно изменить внешний вид меню/HUD | Только `Source/Ui/**/*.vue`; логику (когда что показывать) не трогай, она в `UiController` |
