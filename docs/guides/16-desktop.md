# 16. Десктопная программа и утилита проектов

Инструменты редактора работают как отдельная программа в окнах операционной системы, а не во вкладках браузера.
Оболочка - **Electron**, подключённый к нашей сборке на Vite: он везёт свой Chromium, поэтому инструменты видят тот же
WebGL/WebGPU, wasm и воркеры, что проверяют наши E2E, на всех трёх ОС.

```
src/CSEngine/
  Programs/Desktop/              @cse/desktop - программа: главный процесс Electron, preload, IPC
  Modules/Editor/ProjectBrowser/ @cse/project-browser - утилита проектов (модуль редактора)
  Modules/Editor/UIDesigner/     @cse/ui-designer - редактор интерфейсов (модуль редактора)
```

## Запуск

```
cd src/CSEngine/Modules/Editor/ProjectBrowser && pnpm build
cd src/CSEngine/Modules/Editor/UIDesigner && pnpm build
cd src/CSEngine/Programs/Desktop && pnpm build && pnpm start
```

Программа открывается на утилите проектов. Бинарник Electron скачивается при первом запуске (так устроен пакет
Electron 44: у него нет скрипта установки), дальше берётся из `node_modules/electron/dist`. Для разработки страницы можно взять с dev-серверов Vite:
`CSE_PROJECT_BROWSER_URL=http://127.0.0.1:5177/`, `CSE_UI_DESIGNER_URL=http://127.0.0.1:5175/`. Папку шаблонов и
реестр проектов задают `CSE_TEMPLATES_DIR` и `CSE_PROJECTS_REGISTRY` (по умолчанию - `src/Templates` и реестр
пользователя, см. гайд 13).

## Утилита проектов

Окна утилиты - UI-документы тулкита (`Content/ProjectBrowser.ui.json`, `Content/NewProject.ui.json`), их раскладка
держится на якорях и подстраивается под рамку любой темы.

- **Список** проектов, которые знают движок и инструменты (реестр); пропавший с диска помечен `[missing]`.
- **New project...** - жанр, затем шаблоны этого жанра с описанием (как в Unreal), имя (проверяется на лету: правила
  движка и занятые имена), папка (по умолчанию `~/CSE Projects`, **Browse...** - системный диалог). **Create** копирует
  шаблон со всем шаблонным кодом и регистрирует проект.
- **Open in UI Designer** - дизайнер в собственном окне ОС, проект передаётся ему в адресе (`?project=...`).
- **Remove from list** - проект забывается, его файлы остаются.
- **Theme** - все темы тулкита: 12 классических и Tailwind светлая и тёмная.

## Как устроено

Страница говорит с главным процессом только через `window.cse.projects`, который кладёт preload
(`contextIsolation`, `sandbox`, без Node на странице). Каждый вызов - канал IPC (`projects:list`, `projects:create`...);
главный процесс отвечает `{ ok, value }` или `{ ok: false, error }`, и страница получает обычную ошибку с текстом
главного процесса. Работу с проектами делает `ProjectsService` поверх `Core/BuildTools/Projects.ts`.

Preload собирается отдельным проходом в один файл: preload в `sandbox` может подключать только `electron`.

В обычном браузере (без программы) утилита работает на проектах в памяти (`MemoryProjectsApi`) - для предпросмотра и
тестов.

## Тесты

Юнит-тесты главного процесса, IPC и preload идут в Node с подставным `electron`; E2E (`pnpm test:e2e`) запускает
настоящую программу через Playwright - на Linux без экрана под `xvfb-run`. Под root (контейнеры) Chromium требует
`--no-sandbox`: E2E передаёт его только тогда.

## Дизайнер в программе

Дизайнер работает прямо с проектом:

- из утилиты проектов (**Open in UI Designer**) - в собственном окне ОС на выбранном проекте;
- сам по себе: `pnpm start -- --ui-designer` - сначала спрашивает, для какого проекта делаем UI (список известных
  проектов), затем открывает его.

Слева - панель **Project**: документы из UI-манифеста проекта (открытый выделен, щелчок открывает другой) и поле
нового документа (Id проверяется: идентификатор, не занятый). **Save** (кнопка, меню File, Ctrl+S / Cmd+S) пишет
документ в проект, а не скачивает:

- раскладка - в свой `.ui.json` (новый документ - `<Id>.ui.json` рядом с манифестом) и запись в манифест; она
  проверяется (не раскладка - не сохраняется) и хранится с отступами, читаемой;
- если у документа есть нодовый скрипт - сгенерированный класс в `Source/UI/<Класс>.ts` проекта.

Файлы пишет главный процесс (`DesignerService`, каналы `designer:open`, `designer:read`, `designer:id-problem`,
`designer:save`); любой путь проверяется - ни чтение, ни запись не выходят за папку проекта (и на другой диск в
Windows). В обычном браузере дизайнер, как прежде, открывается на примерах и сохраняет скачиванием.

Обе страницы собираются с относительными путями (`base: "./"`): программа открывает их с диска.

## Редактор кода

Вкладка **Code** дизайнера - редактор кода на Monaco (движок редактора VS Code): подсветка, понимание
TypeScript и JavaScript (ошибки типов подчёркиваются, автодополнение по коду), у каждого языка свой воркер.

- В программе он работает с кодом проекта - его папкой `Source` (только ею: ни остальные файлы проекта, ни что-то вне
  его не доступны); в обычном браузере - с примером в памяти (код, сгенерированный из нодов примера, и файл игры).
- Слева - дерево файлов по папкам, сверху - вкладки открытых файлов; изменённая вкладка помечена **●**, **Ctrl+S**
  (Cmd+S) сохраняет её, закрыть изменённую можно только подтвердив.
- На вкладке Code панель свойств раскладки скрыта - место отдано коду.

Устроено: состояние редактора (файлы, вкладки, изменённость, сохранение) - `CodeSession` поверх `CodeHost`
(список, чтение, запись), без Monaco; `MonacoView` показывает его в Monaco (модель на вкладку); `MonacoSetup`
настраивает воркеры и TypeScript. В программе файлы пишет главный процесс (каналы `designer:code-files`,
`designer:code-read`, `designer:code-write`).

### Типы движка и проекта

Редактор знает типы движка: при сборке дизайнера `Core/BuildTools/EngineTypes.ts` компилирует исходники `@cse/core`
и `@cse/ui` в объявления (`.d.ts`) и кладёт их туда, где их ищет импорт (`file:///node_modules/@cse/...`); короткие
имена из карт экспортов (`@cse/core/modules`, `@cse/ui/game`...) получают файлы-переадресации. Так импорты движка
находятся, а его API подсказывается (у наследника `Component` - `Engine`, `Entity`, `OnCollisionEnter`...).

Языковая служба видит и весь код проекта, а не только открытые файлы: при открытии вкладки Code все файлы TS/JS
проекта загружаются в неё (закрытая вкладка возвращает файлу сохранённый текст - отброшенные правки не видны), поэтому
относительные импорты проекта тоже находятся. Настоящий скрипт шаблона (`Source/Scripts/CoinHunt.ts`) открывается без
единой ошибки - это проверяет E2E программы.

### Где стоит код

**View** → «Code as a tab» (по умолчанию), «Code on the right», «Code on the left», «Code below», «Code above»: код -
отдельной вкладкой или рядом с дизайном с любой стороны, между ними разделитель (его можно тянуть). Выбор отмечен в
меню и запоминается между запусками. Когда код рядом, Ctrl+S сохраняет то, где сейчас клавиатура: в редакторе кода -
файл, на холсте - раскладку; холст в суженной области прокручивается.

Дальше: плавающие окна ОС - код или дизайн в собственном окне.
