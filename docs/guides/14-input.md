# 14. Управление: файлы управления проекта, карты действий, геймпад

Игра спрашивает не «нажат ли пробел», а «нажато ли действие Jump» - как Enhanced Input в Unreal. **Движок не задаёт
ни одного действия и ни одной привязки**: их задаёт проект в своих файлах управления. У каждого действия -
основная и запасная привязка клавиатуры или мыши и одна привязка геймпада; игрок их переназначает. Клавиатура,
мышь и геймпад работают одновременно.

Код: `Core/Source/Engine/Input/InputActions.ts`, `Core/Source/Engine/Services/InputService.ts`.

## Файл управления

`Content/Input/<Id>.input.json` проекта:

```json
{
  "FileVersion": 1,
  "Name": "City",
  "DefaultMap": "OnFoot",
  "ActionMaps": [
    { "Name": "OnFoot", "Actions": [
      { "Name": "Jump", "Label": "Jump", "Category": "Movement", "Default": { "Keyboard": ["Space", ""], "Gamepad": "Pad:A" } },
      { "Name": "EnterCar", "Label": "Get in", "Category": "Actions", "Default": { "Keyboard": ["KeyF", ""], "Gamepad": "Pad:Y" } }
    ] },
    { "Name": "Vehicle", "Actions": [
      { "Name": "Accelerate", "Label": "Accelerate", "Category": "Driving", "Default": { "Keyboard": ["KeyW", ""], "Gamepad": "Pad:RT" } }
    ] }
  ]
}
```

Проект перечисляет свои файлы в дескрипторе:

```json
"Input": { "Manifests": [{ "Id": "City", "Path": "Content/Input/City.input.json" }], "Default": "City" }
```

Файлы читаются при сборке: ошибка в файле называет его и останавливает сборку.

## Два уровня переключения

1. **Файл управления** (`System.UseManifest(id)`). Сцена называет файл, которым она играет (`input: "CoinHunt"` в
   описании сцены); сцена без этого поля играет файлом проекта по умолчанию. Так Games Sample держит файлы всех пяти
   шаблонов, не сливая их в один, и переключается между ними при смене игры. Неизвестный файл - ошибка загрузки
   сцены с его именем.
2. **Карта действий внутри файла** (`System.UseActionMap(name)`), во время игры - как в GTA при посадке в машину:

```ts
if (input.ActionJustPressed("EnterCar")) this.Engine.Input.System.UseActionMap("Vehicle");
```

Файл начинает с карты `DefaultMap`. Переназначения игрока хранятся для каждой карты каждого файла и переживают
переключения; `System.Save()`/`Load()` сохраняют их все.

## Имена действий, которые знают компоненты движка

Компоненты движка обращаются к действиям по именам-соглашениям (их можно поменять в свойствах компонента). Если
активная карта такого действия не содержит, оно просто никогда не нажато.

| Компонент | Действия |
|---|---|
| `MoverComponent` | MoveForward, MoveBack, MoveLeft, MoveRight, Jump, Noclip |
| `CameraComponent` | LookLeft/Right/Up/Down (стик), ToggleView |
| `StrategyCamera` | PanView, ZoomIn, ZoomOut, Recenter, LookLeft/Right/Up/Down (сдвиг вида стиком) |
| `Shooter` | Fire |
| `Sprint` (рецепт) | Sprint |

Коды: клавиши и кнопки мыши как в браузере (`KeyW`, `Space`, `Mouse0`); геймпад - `Pad:A`, `Pad:B`, `Pad:X`,
`Pad:Y`, `Pad:LB`, `Pad:RB`, `Pad:LT`, `Pad:RT`, `Pad:Back`, `Pad:Start`, `Pad:LS`, `Pad:RS`, `Pad:DUp`...; стики -
`Pad:LeftStickUp`, `Pad:RightStickLeft` и так далее.

## В скриптах

```ts
public override OnInputUpdate(input: InputService): void {
	if (input.ActionJustPressed("Restart")) { /* ... */ }
	const [x, y] = input.GetMoveVector();       // Move-действия активной карты: клавиши и стик, длина не больше 1
	const throttle = input.ActionValue("Accelerate"); // 0..1: курок и стик аналоговые
}
```

Стики: мёртвая зона 0.2, за ней значение пересчитывается от 0; нажатием считается больше половины хода.

## Настройки игры

В меню паузы - кнопка **Settings**: список настроек, игрок выбирает строку и меняет значение кнопками Less и More.
Значения сразу уходят в игру; игра хранит их в `SettingsStorage` (ниже), при следующем запуске они возвращаются.

**Общие** объявляет движок - ими управляются его подсистемы:

| Настройка | Что делает |
|---|---|
| Touch controls | сенсорное управление (вместе с клавиатурой и геймпадом; сама сенсорная схема - следующим шагом) |
| Mouse sensitivity | множитель к чувствительности камеры (0.2..3) |
| Invert looking up and down | инверсия обзора по вертикали |
| Gamepad look speed | множитель к скорости обзора правым стиком (0.2..3) |

**Свои** объявляют компоненты игры, когда стартует их сцена, и они уходят вместе со сценой (значения игрока
остаются) - поэтому в меню всегда настройки текущей игры:

```ts
public override Awake(): void {
	this.Engine.Settings.Declare({ Key: "FieldOfView", Label: "Field of view", Category: "First Person",
		Kind: "Number", Default: 70, Min: 60, Max: 100, Step: 5 });
}
public override Update(): void {
	camera.FovDegrees = this.Engine.Settings.Number("FieldOfView");
}
```

Виды: `Toggle` (вкл/выкл), `Number` (в пределах `Min`..`Max` с шагом `Step`), `Choice` (один из `Choices`).
Значения проверяются: число прижимается к пределам и шагу, чужой вариант и значение не того вида не принимаются.
В шаблонах: First Person - поле зрения, Third Person - дистанция камеры, Top-Down - прокрутка от края экрана
(её объявляет `StrategyCamera`), Coin Hunt - лимит времени (заданный в сцене лимит - значение по умолчанию).

Экран настроек - документ движка `EngineSettings`; проект может заменить его своим, как и меню паузы.

## SettingsStorage: где живёт то, что выбрал игрок

Как `PlayerPrefs` в Unity: JSON-значения по ключам поверх хранилища платформы (`Core/Source/Engine/Storage`).
Игра обращается к нему как `this.Engine.Storage`:

```ts
const progress = this.Engine.Storage.Get("Progress", { Level: 1 }); // сразу, из кеша
this.Engine.Storage.Set("Progress", { Level: 2 });                   // запись уходит в фоне, по порядку
```

Движок сам хранит два ключа - простые, понятные JSON:

| Ключ | Что | Пример |
|---|---|---|
| `Settings` | значения настроек игрока (всех игр проекта) | `{ "MouseSensitivity": 1.5, "TimeLimit": "30" }` |
| `Input` | переназначения управления: файл → карта → действие | `{ "FirstPerson": { "OnFoot": { "Fire": { "Keyboard": ["KeyF", ""], "Gamepad": "Pad:RT" } } } }` |

`Export()` отдаёт всё одним читаемым JSON, `Import(text)` возвращает (резервная копия игрока).

**В браузере** хранилище - IndexedDB, одна база на проект (`cse:<имя проекта>`): она большая, асинхронная,
работает в воркере игровой логики и не требует ничего от хоста (ни заголовков, ни настроек сервера). Страница при
старте просит браузер о постоянном хранилище (`navigator.storage.persist()`): в Chrome, Firefox и Safari 17+ такое
хранилище не вытесняется при нехватке места; браузер может и отказать - ответ пишется в лог.

Честные ограничения, которые не обойти без своего сервера:

- **Safari** стирает всё хранилище сайта после 7 дней использования Safari без визита на сайт - это касается
  любого хранилища, в которое пишет скрипт (IndexedDB, localStorage, OPFS). Исключение - игра, установленная на
  домашний экран.
- Сайт, **встроенный в чужую страницу** (игровой портал), получает в современных браузерах своё хранилище на каждый
  такой портал.
- Где IndexedDB недоступна (некоторые приватные режимы), хранилище работает в памяти, а лог говорит почему.
## Переназначение управления

В экране настроек - кнопка **Controls**: список всех действий файла управления, которым играет текущая игра, по
картам и категориям, с тремя привязками - основная клавиша, запасная и кнопка геймпада:

`[OnFoot · Movement] Jump: Space · J · Pad A`

Игрок выбирает строку, затем ячейку (**Main key**, **Spare key**, **Gamepad**) и нажимает то, что должно делать
действие: клавишу или кнопку мыши для клавиатурных ячеек, кнопку или стик геймпада - для ячейки геймпада (то, что
было зажато в момент начала, не считается). **Esc** отменяет, **Delete** или **Backspace** очищают ячейку,
**Reset all** возвращает умолчания файла. Изменение сразу действует в игре и записывается в `SettingsStorage`
(ключ `Input`), так что переживает перезагрузку.

Как устроено: экран (документ движка `EngineControls`, его можно заменить своим) говорит с игрой по каналу
плагина `input`; в игре на нём отвечает `InputBindings` (`Core/Source/Engine/Input/InputBindings.ts`):

| Со страницы | Что делает игра |
|---|---|
| `{ op: "request" }` | присылает снимок: файл, активная карта, все карты с действиями и привязками |
| `{ op: "rebind", map, action, slot, code }` | меняет привязку, сохраняет, присылает снимок |
| `{ op: "reset", map?, action? }` | возвращает умолчания (одного действия, карты или всех), сохраняет, присылает снимок |

Ошибка (нет такой карты или действия) приходит как `{ op: "error", message }` и показывается в подсказке.
## Сенсорная схема

Общая настройка **Touch controls** включает экранные стики и кнопки - вместе с клавиатурой и геймпадом, а не вместо
них. Пока она включена, игра не захватывает мышь ни в одной сцене (на телефоне захвата нет), а паузу ставит
экранная кнопка **II** (и Esc, если клавиатура есть). Слой виден только во время игры - не в меню и не при загрузке.

Элементы берутся из **действий активной карты** файла управления. Какой элемент нажимает действие, говорит его
поле `Touch`:

| `Touch` | Элемент | По умолчанию для |
|---|---|---|
| `MoveStick` | стик движения (слева внизу) | действий, чьё имя начинается с `Move` |
| `LookStick` | стик обзора (справа внизу) | действий, чьё имя начинается с `Look` |
| `Button` | кнопка с подписью действия (над правым стиком) | всех остальных |
| `None` | ничего | - (шаблоны так помечают отладочный «полёт» и перетаскивание вида мышью) |

Стик раскладывает своё положение на действия по окончанию их имени: `...Forward`/`...Up` - вверх, `...Back`/`...Down`
- вниз, `...Left`, `...Right`. В игре это «виртуальные» нажатия действий (`InputService.SetTouch`): они складываются
с клавишами и геймпадом и дают «нажато» и «только что нажато» так же, как клавиши. Сменилась карта (сели в машину) -
слой показывает её действия.

Стики и кнопки - элементы тулкита `WinJoystick` и `WinGameButton` (гайд 10), поэтому слой выглядит в теме игры.
### Расстановка

Settings → Controls → **Arrange touch**: экран затемняется, элементы перестают нажиматься и перетаскиваются куда
удобнее (взятый элемент приподнимается); другой палец переноса не перехватывает. **Done** сохраняет раскладку и
возвращает на экран управления, **Reset** - места по умолчанию (стики по нижним углам, кнопки рядами над правым
стиком, пауза сверху справа).

Раскладка - центр каждого элемента в долях экрана, по ключу: `MoveStick`, `LookStick`, `Button:<действие>`,
`Pause`. Игра хранит её в `SettingsStorage` ключом `TouchLayout` отдельно для каждого файла управления (у разных
игр разные элементы) и присылает вместе со снимком действий; страница отдаёт её на сохранение сообщением
`{ op: "touch-layout", layout }` по каналу `input`:

```json
{ "FirstPerson": { "MoveStick": { "X": 0.4, "Y": 0.35 }, "Button:Jump": { "X": 0.9, "Y": 0.45 } } }
```
